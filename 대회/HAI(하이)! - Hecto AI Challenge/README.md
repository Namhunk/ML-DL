# HAI(하이)! - Hecto AI Challenge: 딥페이크 탐지 AI 모델 개발

### [Competition Link](https://dacon.io/competitions/official/236628/overview/description)

## 대회 개요

- **과제:** 다양한 이미지(jpg, jpeg, png, jfif) 또는 동영상(mp4, mov) 데이터를 **이미지 단위로 입력**받아, 해당 콘텐츠가 진짜(Real)인지 딥페이크(Fake)인지 분류
- **주최/주관:** 헥토(Hecto)
- **운영:** Dacon
- **기간:** 2025.12.29 - 2026.02.02
- **성과:** 최종 **39등 / 458**

## 평가 지표

**ROC-AUC (with Sample Weights)** — 샘플별 가중치는 비공개

- Public: 전체 테스트 데이터 중 사전 샘플링된 50%
- Private: 전체 테스트 데이터 100%

## 베이스라인

파이프라인 골격은 Dacon 공식 베이스라인을 사용하고, 두 부품만 교체

| 단계 | baseline | 사용 |
| :--- | :--- | :--- |
| 얼굴 검출 | 기본 검출기 | **YOLO 로 교체** |
| 분류 모델 | ViT 사전학습 | **GenD 사전학습** |

crop 이후의 전처리(리사이즈·정규화 등)와 프레임별 결과 종합 방식은 손대지 않음

## 접근 방법

### 1. 얼굴 검출 — YOLO

얼굴 영역만 crop해 분류기에 넣는 구조 자체는 baseline 그대로이고, **검출기만 YOLO로 교체**

- 추론 시간이 전체 평가셋 기준 60분으로 제한된 대회\
  프레임 수가 많은 동영상에서는 검출 단계의 처리량이 곧 파이프라인 전체의 병목
- 검출 결과의 crop 이후 단계(리사이즈·정규화)는 baseline과 동일하게 유지

### 2. 분류 모델 — GenD

- 모델: [yermandy/GenD](https://huggingface.co/collections/yermandy/gend)
- baseline의 범용 ViT 대신 **딥페이크 탐지용으로 사전 학습된 가중치**를 사용\
  학습 데이터를 직접 수집해야 하는 대회 특성상, 데이터 확보 부담과 일반화 문제를 함께 회피하기 위한 선택

## 회고

**잘 된 점**

- 직접 학습 대신 도메인 특화 사전 학습 모델(GenD)을 채택\
  baseline 골격에 부품 두 개만 교체해 적은 비용으로 상위권 진입

**개선할 점**

- **crop 이후 전처리를 baseline에서 전혀 바꾸지 않음**\
  crop margin·얼굴 해상도 정규화·프레임 샘플링 간격처럼 즉시 조정 가능한 변수조차 비교 실험하지 못함
- **딥페이크 특화 입력 표현을 시도하지 못함**\
  JPEG 압축 아티팩트, 고주파 residual(SRM 필터), 주파수 영역 변환(FFT/DCT) 등 생성 모델의 흔적을 직접 겨냥하는 전처리가 이 문제의 핵심인데 손대지 못함
- **규칙상 앙상블·다중 백본·TTA가 모두 금지된 대회라 전처리와 학습 데이터가 유일한 차별화 축이었음**\
  그 축을 baseline 그대로 둔 채 사전 학습 모델 성능에만 의존해, 개선 폭을 스스로 만들지 못한 것이 가장 큰 아쉬움
- **외부 데이터로 fine-tuning 하지 않고 사전 학습 가중치를 그대로 사용**\
  공식 학습 데이터가 없는 대신 규칙이 외부 데이터 수집·생성을 명시적으로 허용했으므로, 도메인에 맞춘 추가 학습이 가장 큰 상승 여지였을 가능성
- 프레임별 예측을 하나의 영상 라벨로 합치는 집계 방식(평균/최댓값/투표) 비교 기록 부재\
  후처리 종합은 규칙이 허용한 몇 안 되는 여지인데 baseline 방식을 그대로 사용
